# 手写近况与文章补记

正文、近况和补记都由网站作者本人撰写。网站仅负责排版，不从聊天、文件修改时间、阅读记录或自动日报推断新的个人内容。

## 首页近况

编辑 `src/content/now.md`。普通 Markdown 段落、列表和链接都可以使用；建议保留简短的两三句话。

```markdown
---
updated: 2026-09-07
draft: false
---

在这里写你愿意公开的近况。
```

`updated` 是你确认的近况更新日期，不会随构建自动刷新，也不是阅读完成日期。不填写日期时不显示更新时间。设为 `draft: true`，或清空正文，首页就不会显示近况区域。该文件没有独立公开页面。

## 在原文章末尾写补记

打开原来的 `src/content/blog/` 下的 Markdown 文件，在末尾空一行，然后写：

```markdown
> [!update] 2026-09-07
> 在这里写你后来补充或修正的内容。
>
> 可以继续写第二段，也可以加 **强调**、公式和 [相关链接](/)。
```

- 第一行只写 `[!update]` 和实际日期，使用 `YYYY-MM-DD` 格式。
- 后续每一行以 `>` 开头，空行写成单独的 `>`。这仍是普通 Markdown 引用块，无需 HTML 或前端代码。
- 网站把这种顶层引用块显示为带日期的“补记”；建议放在文章末尾，也可以由你决定其位置。
- 多次补记之间留一个**不带 `>` 的空行**，各写一块。网站按你写的顺序展示，不自动重排。
- Markdown 公式、代码、图片和链接沿用原文章的处理流程。代码块里的示例标记不会被当作补记。
- 没有补记的文章不出现空栏目。既有正文、发布日期和文章列表排序不受影响。
- 无效日期或没有正文的补记会让构建报错，防止误发布空内容。
- 这个写法只对 Blog 生效，不改变 Paper Radar，也不改 Obsidian / Zotero 的文件或导出方式。

## 验证

运行 `ASTRO_TELEMETRY_DISABLED=1 npm run build`，然后运行 `node scripts/verify-authoring.mjs`、`node scripts/verify-reading-site.mjs` 和 `node scripts/verify-theme.mjs`。

不要自动给历史文章添加示例补记。测试示例只在验证脚本里，不会作为作者内容发布。
